# ADR 0009: DSL Context Types for Constrained Child Components

Mosaik will keep raw kotlinx.html receivers for simple components, but compound components with semantic child components will use public prefixed DSL context types to enforce valid child placement at compile time. This deliberately narrows ADR 0003 for compound components: the context type should still behave like the underlying valid HTML element where possible (for example `MCardContent : DIV`), while child components attach only to the narrowest valid context such as `MCardBodyContent`; a shared `@MosaikDsl` marker in `Theme.kt` prevents child-component leakage into nested ordinary HTML blocks. We accept the extra public generated-source API because invalid structures like card titles outside card bodies are semantic errors that should not be suggested by autocomplete or compile successfully.
